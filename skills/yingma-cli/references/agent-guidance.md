# Agent 对话引导

仅在用户要求通过 Agent 使用小影马、需要确认下一步，或任务包含画布修改、提示词处理、视频精修时阅读。本引导只适用于 Agent 流水线和无限画布。

## 安装后的首轮回复

安装完成并运行 `yingma doctor` 后，不要假定用户想登录或创作。只回报安装、自检、登录态和项目绑定，并给出三个明确方向：

1. 登录本机 CLI；
2. 检查并继续一个已有项目；
3. 创建一个新的短剧、广告或画布方案。

如果 CLI 已登录但当前目录没有绑定项目，先用 `yingma project list` 让用户选项目，或请用户授权新建。不要从项目名猜测 ID。

## 已有项目：先诊断，再动手

当用户说“继续这个项目”“修一下画布”或“看看哪里卡住了”时，先读取：

```bash
yingma project get
yingma canvas summary
yingma canvas node list
yingma artifact list
yingma episode list
```

报告应包含：当前项目/画布、异常节点或悬空连线、可能的最小修改，以及每项修改是否会写入或消耗积分。然后只准备 `--dry-run`，等待确认；不要顺手修改、重跑、生成或渲染。

## 从创作目标到可确认的方案

用户给出短剧、广告或一个镜头想法时，先把目标转成可检查的交付物：项目类型、画幅/语言、素材来源、画布节点、确认点。若用户还没授权创建项目，只返回方案；若已明确授权创建，则创建项目和画布，但在任何生成前停下。

建议按以下格式确认：

> 我会在项目 `…` 的画布 `…` 上处理节点 `…`。这一步会【创建节点 / 修改提示词 / 提交视频精修 / 发起模型任务】，预计影响 `…`。我已准备好预演；确认后才会执行真实请求。是否继续？

不要捏造积分或任务成功状态。无法取得费用预估时，明确写“实际费用以提交后的平台返回为准”。

## 画布提示词与媒体精修

提示词翻译、优化、反推，以及分镜预览、主体素材、图片擦除、视频重拍、裁剪、分割、变帧、高清、擦除、音画分离、景深和音频编辑都会写入项目或排队任务。必须先说明：

- 目标节点 ID 和当前素材；
- 具体参数，例如时间段、裁剪区域、清晰度或插帧；
- 是否会提交模型或后台任务；
- `--dry-run` 的结果，随后才请求确认并使用 `--yes`。

例如先执行：

```bash
yingma canvas video trim --id VIDEO_NODE --start-sec 1.5 --end-sec 6.5 --yes --dry-run
```

确认后才去掉 `--dry-run`。如果用户只想“看看怎么剪”，不要提交任务。

## 执行后的回复

每次真实写入或任务提交后，返回以下四项：

1. 已完成的动作和真实项目/画布/节点 ID；
2. 平台返回的任务状态或错误；
3. 没有执行的高风险下一步；
4. 一句需要用户确认的继续选项。

示例：

> 已为视频节点 `…` 提交 1080p 高清任务，平台状态为 `queued`。我没有生成新的镜头或渲染成片。完成后可先检查结果，或在你的确认下继续做下一处精修。
